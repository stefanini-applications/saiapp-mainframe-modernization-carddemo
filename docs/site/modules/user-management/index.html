👥 User Management

User Story Development Guide · CardDemo Module

📋 Overview

Purpose: Admin-only CRUD functions for managing CardDemo user accounts: list, add, update, and delete.

Business Context: User Management controls who can access CardDemo. Only users with SEC-USR-TYPE = A can access the Admin Menu and these functions. The user security file is a VSAM PS file.

CA00 · COADM01C CU00 · COUSR00C CU01 · COUSR01C CU02 · COUSR02C CU03 · COUSR03C

🎯 User Story Templates

  • As an admin, I want to list all registered users so that I can audit who has system access.
  • As an admin, I want to add a new user with ID, name, password, and type so that they can log in immediately.
  • As an admin, I want to update an existing user's password so that I can assist with password resets.
  • As an admin, I want to delete a user so that I can revoke access for departed employees.
  • As the system, I want to prevent duplicate user IDs so that each user has a unique login.

Acceptance Criteria

Given: admin navigates to List Users (CU00)
Then:  all users displayed with SEC-USR-ID, SEC-USR-FNAME, SEC-USR-LNAME, SEC-USR-TYPE

Given: admin submits new user with unique SEC-USR-ID
When:  COUSR01C processes CU01 transaction
Then:  new SEC-USER-DATA record written to USRSEC.PS
And:   confirmation "User added" displayed

Given: admin attempts to add a user with an existing SEC-USR-ID
When:  COUSR01C checks the VSAM file
Then:  error "User ID already exists" displayed and no record written

Given: admin confirms deletion of a user
When:  COUSR03C processes CU03 transaction
Then:  user record deleted from USRSEC.PS
And:   user can no longer log in

🔧 Technical Foundation

User Security Record (CSUSR01Y — 80 bytes)

SEC-USR-ID      PIC X(08)  -- Unique user ID (VSAM key)
SEC-USR-FNAME   PIC X(20)  -- First name
SEC-USR-LNAME   PIC X(20)  -- Last name
SEC-USR-PWD     PIC X(08)  -- Password (plaintext in demo)
SEC-USR-TYPE    PIC X(01)  -- U=Regular User, A=Admin
ComponentResponsibility
COADM01C.cblAdmin Menu routing (CA00)
COUSR00C.cblList users with paging
COUSR01C.cblAdd new user with duplicate check
COUSR02C.cblUpdate user fields (password, name, type)
COUSR03C.cblDelete user with confirmation
AWS.M2.CARDDEMO.USRSEC.PSVSAM PS user security file

📊 Complexity Guidelines

Simple (1–2 pts)List users; view user details
Medium (3–5 pts)Add user with validation; update password; delete with confirmation
Complex (5–8 pts)Role-based permission model; password policy enforcement; audit log for user changes
