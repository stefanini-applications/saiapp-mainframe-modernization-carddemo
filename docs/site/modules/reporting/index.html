📊 Reporting

User Story Development Guide · CardDemo Module

📋 Overview

Purpose: Allow users to request transaction category reports online; reports are generated by a CICS-submitted batch job (TRANREPT).

Business Context: Reports provide spending analysis by transaction category. The online screen (CR00) accepts report parameters and submits the TRANREPT JCL to the internal reader. Output is written to a print dataset or GDG.

CR00 · CORPT00C TRANREPT · CBTRN03C

🎯 User Story Templates

  • As a regular user, I want to request a transaction category report so that I can see my spending broken down by category.
  • As a business analyst, I want to review generated transaction statements so that I can validate billing accuracy.
  • As an operations engineer, I want the report job to run reliably so that outputs are always available after the batch window.

Acceptance Criteria Examples

Given: user submits report request on CR00 screen
When:  CORPT00C submits TRANREPT JCL via internal reader
Then:  batch job TRANREPT is queued for execution
And:   confirmation message displayed on screen

Given: TRANREPT batch job runs successfully
When:  CBTRN03C processes transactions from TRANSACT.VSAM.KSDS
Then:  report output written with transaction totals by category
And:   return code is 0
