📨 MQ Integration

User Story Development Guide · CardDemo Optional Module

⚠️ Optional Module — Requires IBM MQ infrastructure

📋 Overview

Purpose: Expose CardDemo data (account details, system date) to distributed systems via IBM MQ request/response messaging.

Business Context: Demonstrates asynchronous MQ patterns: a remote system sends a request to an MQ queue; the CICS program receives it, looks up VSAM data, and sends the response to a reply queue. Two transactions are available: system date inquiry (CDRD) and account details inquiry (CDRA).

CDRD · CODATE01 CDRA · COACCT01

🎯 User Story Templates

  • As a distributed application, I want to request the current mainframe system date via MQ so that I can synchronize timestamps with the host.
  • As a partner system, I want to request account details for a given account ID via MQ so that I can display account information in a remote UI.

Acceptance Criteria

Given: client sends MQ message to CDRD queue with reply-queue name
When:  CODATE01 (CDRD) processes the message
Then:  current system date written to the MQ reply queue

Given: client sends MQ message to CDRA queue with valid ACCT-ID
When:  COACCT01 (CDRA) looks up account in VSAM ACCTDATA.PS
Then:  account details (balance, limit, status) written to MQ reply queue

Given: ACCT-ID in CDRA request does not exist in VSAM
When:  COACCT01 processes the request
Then:  error response written to reply queue with "Account not found" indicator

🔧 Technical Foundation

ComponentResponsibility
CODATE01.cblCICS MQ system date inquiry (CDRD)
COACCT01.cblCICS MQ account details inquiry (CDRA)
AWS.M2.CARDDEMO.ACCTDATA.PSAccount master VSAM (CDRA read source)

MQ Message Pattern

-- Request (client → CardDemo)
MQMD: Reply-to queue name
MQBODY: Request type + parameters (ACCT-ID for CDRA)

-- Response (CardDemo → client)
MQMD: Correlation ID matching request
MQBODY: Response data or error indicator

Dependencies

  • account-management: CDRA reads CVACT01Y account record from VSAM
  • IBM MQ: Queue manager and queues must be configured (CRDDEMOM.csd for CICS MQ resources)

📊 Complexity Guidelines

Simple (2–3 pts)System date inquiry via MQ (CDRD)
Medium (5–8 pts)Account details inquiry via MQ (CDRA) with VSAM lookup and error handling
Complex (8–13 pts)New MQ-based service; multi-field inquiry; correlation ID tracking; timeout and retry handling
