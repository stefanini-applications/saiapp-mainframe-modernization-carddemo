User Story Development Guide · CardDemo Module

📋 Overview

Purpose: Enable users to browse transaction history, view individual transaction details, and add new transactions against a card.

Business Context: Transactions are the heart of the credit card lifecycle. Online transactions are stored in a VSAM KSDS file; daily transactions accumulate in a sequential file and are merged by the batch POSTTRAN job. Type and category codes classify spending for reporting and interest calculation.

CT00 · COTRN00C CT01 · COTRN01C CT02 · COTRN02C

🎯 User Story Templates

  • List Transactions: As a regular user, I want to browse my transaction history so that I can review and reconcile charges.
  • View Transaction Detail: As a regular user, I want to view all fields of a specific transaction so that I can verify merchant, amount, and date.
  • Add Transaction: As a regular user, I want to add a new transaction for a merchant purchase so that it is recorded against my card.
  • Validate Type/Category: As the system, I want to validate transaction type and category codes so that only valid reference codes are accepted.

Acceptance Criteria Examples

Given: card with 15 existing transactions in TRANSACT.VSAM.KSDS
When:  user opens Transaction List (CT00)
Then:  transactions displayed in reverse chronological order with paging

Given: user submits valid transaction (type, category, amount, merchant)
When:  COTRN02C processes the CT02 transaction
Then:  new TRAN-RECORD written to TRANSACT.VSAM.KSDS
And:   TRAN-ID is system-generated and unique

Given: user submits transaction with invalid TRAN-TYPE-CD
When:  COTRN02C validates the code against TRANTYPE.PS
Then:  error message "Invalid transaction type" displayed
And:   no record written to VSAM

Given: ACCT-ACTIVE-STATUS = N for the linked account
When:  user attempts to add a transaction (CT02)
Then:  transaction rejected with "Account inactive" error

📊 Complexity Guidelines

Simple (1–2 pts) View transaction detail; read-only inquiry by TRAN-ID
Medium (3–5 pts) Add transaction with type/category validation; list with VSAM browse and paging
Complex (5–8 pts) Transaction reversal/adjustment; cross-file integrity (account balance check at add time); batch POSTTRAN integration testing

⚡ Development Acceleration

  • AIX on CARD-NUM: TRANSACT.VSAM.KSDS has an alternate index on TRAN-CARD-NUM; use it to list all transactions for a card without full-file scan
  • Reference files are small: TRANTYPE and TRANCATG are loaded into working storage for validation — no repeated VSAM reads per transaction
  • Sample data: app/data/ASCII/dailytran.txt provides realistic test transactions
  • TRAN-ID generation: Follow the existing pattern in COTRN02C (timestamp + sequence) to guarantee uniqueness
