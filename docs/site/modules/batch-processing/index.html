⚙️ Batch Processing

User Story Development Guide · CardDemo Module

📋 Overview

Purpose: End-of-day batch cycle that posts transactions, calculates interest, generates statements, refreshes VSAM files, and produces reports.

Business Context: Batch processing is the financial engine of CardDemo. All account balance changes from daily transactions, interest accruals, and statement generation happen here. The batch window requires CICS files to be closed; CLOSEFIL and OPENFIL JCLs bracket the batch run.

🎯 User Story Templates

  • As an operations engineer, I want to run the daily batch cycle so that end-of-day processing completes and account balances are updated.
  • As an operations engineer, I want to monitor batch job return codes so that I can detect and resolve failures quickly.
  • As a business analyst, I want transaction statements generated so that customers receive accurate billing.
  • As a finance team member, I want interest calculations to run automatically so that interest charges are applied to outstanding balances.

Acceptance Criteria

Given: all VSAM files closed by CLOSEFIL
When:  POSTTRAN (CBTRN02C) runs against DALYTRAN.PS
Then:  all valid transactions posted to TRANSACT.VSAM.KSDS
And:   ACCT-CURR-BAL updated for each affected account
And:   rejected transactions written to reject file
And:   return code = 0

Given: INTCALC runs after POSTTRAN
When:  CBACT04C reads TCATBALF interest rates
Then:  interest charges applied to accounts with outstanding balances

Given: CREASTMT runs
When:  CBSTM03A generates statements
Then:  output written to GDG generation
And:   each active account with transactions has a statement
