🏷️ Transaction Type Management

User Story Development Guide · CardDemo Optional Module

⚠️ Optional Module — Requires DB2 subsystem with precompiler support

📋 Overview

Purpose: Admin maintenance of transaction type reference data in DB2 tables, synchronized to VSAM files used by the base application.

Business Context: Transaction types classify purchases for interest calculation and reporting. This module demonstrates DB2 embedded static SQL patterns including forward/backward cursor navigation, CRUD operations, and the DB2-to-VSAM extract flow.

CTLI · COTRTLIC CTTU · COTRTUPC MNTTRDB2 · COBTUPDT TRANEXTR · DSNTIAUL

🎯 User Story Templates

  • As an admin, I want to list all transaction types in DB2 so that I can review the current reference data.
  • As an admin, I want to add a new transaction type so that it is available for use in transaction processing.
  • As an admin, I want to update a transaction type description so that it accurately reflects its business meaning.
  • As an admin, I want to delete an obsolete transaction type so that the reference list is kept clean.
  • As an operations engineer, I want to run the TRANEXTR batch job after DB2 updates so that VSAM files used by the base application are synchronized.

Acceptance Criteria

Given: admin navigates to CTLI (Transaction Type List)
When:  COTRTLIC opens a DB2 cursor on TRNTYPE table
Then:  transaction types displayed with type code and description
And:   forward/backward paging works via cursor navigation

Given: admin adds new type via CTTU (COTRTUPC)
When:  INSERT INTO TRNTYPE executed with new code and description
Then:  new row visible in CTLI list
And:   SQLCODE = 0

Given: admin deletes a type referenced by existing transactions
When:  COTRTLIC attempts DELETE
Then:  error "Type in use — cannot delete" displayed

Given: TRANEXTR batch job runs after DB2 updates
When:  DSNTIAUL extracts TRNTYPE and TRNTYCAT tables
Then:  VSAM TRANTYPE.PS and TRANCATG.PS updated with latest data
