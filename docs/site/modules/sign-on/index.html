🔐 Sign-On

User Story Development Guide · CardDemo Module

📋 Overview

Purpose: Authenticate CardDemo users (regular and admin) and establish a CICS session with appropriate routing.

Business Context: Every user interaction with CardDemo starts here. The sign-on validates credentials against the VSAM user security file and sets the COMMAREA user type flag that determines which menu is presented.

CICS Transaction: CC00 Program: COSGN00C Map: COSGN00.bms

🎯 User Story Templates

Core Stories

  • Login (Regular User): As a regular user, I want to enter my user ID and password so that I can access my account and card management functions.
  • Login (Admin): As an admin user, I want to authenticate with my admin credentials so that I can access administrative functions.
  • Invalid Credentials: As a user, when I enter incorrect credentials, I want to see a clear error message so that I know my login failed and can retry.
  • Session Routing: As a user, after successful login I want to be routed to the appropriate menu for my role so that I only see functions I am authorized to use.

Acceptance Criteria Examples

Given: valid user ID (SEC-USR-TYPE=U) and correct password
When:  I submit the sign-on screen (CC00)
Then:  Main menu (CM00) is displayed with user-level options

Given: valid admin ID (SEC-USR-TYPE=A) and correct password
When:  I submit the sign-on screen
Then:  Admin menu (CA00) is displayed with administrative options

Given: any user ID with an incorrect password
When:  I submit the sign-on screen
Then:  An error message is displayed and the sign-on screen is re-presented

Given: a user ID not found in AWS.M2.CARDDEMO.USRSEC.PS
When:  I submit the sign-on screen
Then:  An error message "User not found" is displayed

Data Structure — SEC-USER-DATA (CSUSR01Y)

SEC-USR-ID      PIC X(08)  -- Login ID
SEC-USR-FNAME   PIC X(20)  -- First name
SEC-USR-LNAME   PIC X(20)  -- Last name
SEC-USR-PWD     PIC X(08)  -- Password
SEC-USR-TYPE    PIC X(01)  -- U=Regular User, A=Admin

Dependencies

  • VSAM USRSEC.PS: Must be loaded (DUSRSECJ JCL) before first login
  • CICS COMMAREA: Passes user type to main-menu for role-based routing
  • RACF: Provides environment-level security (CICS region access)

📊 Complexity Guidelines

Simple (1–2 pts) Display sign-on screen; show error message on failure
Medium (3–5 pts) Add account lockout after N failed attempts; password change requirement
Complex (5–8 pts) RACF integration; multi-factor token validation; audit trail for all login attempts

⚡ Development Acceleration

  • Existing BMS map (COSGN00.bms): Screen layout already defined; modify only field attributes
  • VSAM read pattern: Direct key read on SEC-USR-ID; reuse pattern from COUSR00C
  • COMMAREA contract: COCOM01Y defines the shared structure; do not change field offsets
  • Default credentials: ADMIN001/PASSWORD and USER0001/PASSWORD pre-loaded in sample data
