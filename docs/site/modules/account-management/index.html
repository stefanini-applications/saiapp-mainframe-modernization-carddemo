🏦 Account Management

User Story Development Guide · CardDemo Module

📋 Overview

Purpose: View and update credit card account information including current balance, credit limits, and key dates.

Business Context: Account Management is the financial core of CardDemo. Balances are updated by the POSTTRAN batch job; limits and dates can be modified online. All other modules (cards, transactions, bill payment) depend on account data.

View Transaction: CAVW · COACTVWC Update Transaction: CAUP · COACTUPC

🎯 User Story Templates

  • View Balance: As a regular user, I want to view my current balance and available credit so that I can plan my spending.
  • View Account Details: As a regular user, I want to see account open date, expiration date, and group ID so that I have a full picture of my account.
  • Update ZIP Code: As a regular user, I want to update my account ZIP code so that my billing address is current.
  • Admin Limit Change: As an admin, I want to update the credit limit on an account so that I can respond to customer upgrade requests.
  • Activate/Deactivate Account: As an admin, I want to change the account active status so that I can suspend or restore account access.

Acceptance Criteria Examples

Given: authenticated user with a valid ACCT-ID
When:  user navigates to Account View (CAVW)
Then:  ACCT-CURR-BAL, ACCT-CREDIT-LIMIT, ACCT-OPEN-DATE, ACCT-EXPIRAION-DATE displayed

Given: admin submits account update with new credit limit
When:  COACTUPC processes the CAUP transaction
Then:  ACCT-CREDIT-LIMIT updated in VSAM ACCTDATA.PS
And:   Confirmation message displayed on screen

Given: ACCT-ACTIVE-STATUS = N
When:  user attempts to add a transaction via CT02
Then:  Transaction rejected with "Account inactive" message

Account Record (CVACT01Y — 300 bytes)

ACCT-ID                  PIC 9(11)     -- Primary key (11-digit account number)
ACCT-ACTIVE-STATUS       PIC X(01)     -- Y=Active, N=Inactive
ACCT-CURR-BAL            PIC S9(10)V99 -- Current balance (COMP-3)
ACCT-CREDIT-LIMIT        PIC S9(10)V99 -- Total credit limit
ACCT-CASH-CREDIT-LIMIT   PIC S9(10)V99 -- Cash advance limit
ACCT-OPEN-DATE           PIC X(10)     -- YYYY-MM-DD
ACCT-EXPIRAION-DATE      PIC X(10)     -- YYYY-MM-DD
ACCT-REISSUE-DATE        PIC X(10)     -- YYYY-MM-DD
ACCT-CURR-CYC-CREDIT     PIC S9(10)V99 -- Credits this cycle
ACCT-CURR-CYC-DEBIT      PIC S9(10)V99 -- Debits this cycle
ACCT-ADDR-ZIP            PIC X(10)     -- Billing ZIP
ACCT-GROUP-ID            PIC X(10)     -- Customer segment

Dependencies

  • sign-on: Must be authenticated; COMMAREA carries user context
  • batch-processing (POSTTRAN): Updates ACCT-CURR-BAL and cycle totals nightly
  • credit-card-management: Cards reference ACCT-ID for linkage
  • bill-payment: Payment reduces ACCT-CURR-BAL directly

📊 Complexity Guidelines

Simple (1–2 pts) Display account view screen; read-only balance inquiry
Medium (3–5 pts) Update credit limit with validation; change active status; update ZIP
Complex (5–8 pts) Credit limit change requiring approval workflow; real-time balance recalculation; multi-account batch update

⚡ Development Acceleration

  • VSAM KSDS direct read: ACCT-ID is the primary key; O(1) lookup — reuse the read pattern from COACTVWC
  • BMS map already defined: COACTUP.bms layout covers all updateable fields
  • Sample data: app/data/ASCII/acctdata.txt contains test accounts for development
  • COMMAREA: Account context (ACCT-ID) passed from main menu; no need to re-prompt user
