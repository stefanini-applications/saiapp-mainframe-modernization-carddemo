🔒 Authorization

User Story Development Guide · CardDemo Optional Module

⚠️ Optional Module — Requires IMS DB, DB2, and IBM MQ infrastructure

📋 Overview

Purpose: Real-time credit card authorization processing via IBM MQ, with authorization storage in IMS hierarchical database and fraud reporting in DB2.

Business Context: Simulates a POS authorization flow: a merchant system sends an authorization request via MQ; CardDemo validates account status, credit limit, and card expiry; approves or declines; stores in IMS; and returns response via reply queue. Suspicious transactions can be flagged as fraud in DB2.

CPVS · COPAUS0C CPVD · COPAUS1C CP00 · COPAUA0C (MQ trigger) CBPAUP0J · CBPAUP0C (Batch)

🎯 User Story Templates

  • As a POS system, I want to submit an authorization request via MQ so that real-time approval or decline is processed.
  • As a cardholder, I want to view my pending authorizations so that I can track recent activity.
  • As a fraud analyst, I want to mark a suspicious authorization as fraudulent so that it is escalated to DB2 for analytics.
  • As an operations engineer, I want to run the batch purge of expired authorizations so that stale records are removed and available credit is restored.

Acceptance Criteria

Given: valid MQ authorization request with CARD-NUM, AUTH-AMT, MERCHANT-ID
When:  COPAUA0C (CP00) is triggered by MQ message
Then:  account looked up via CARDXREF and ACCTDATA
And:   if ACCT-ACTIVE-STATUS=Y and credit available: response = APPROVED
And:   authorization record stored in IMS DBPAUTP0
And:   response sent to MQ reply queue within 500ms

Given: authorization request for expired card (CARD-EXPIRAION-DATE in past)
When:  COPAUA0C processes the request
Then:  response = DECLINED with reason code "EXPIRY"

Given: fraud analyst marks authorization as AUTH-FRAUD=Y in COPAUS1C (CPVD)
When:  COPAUS2C writes to DB2
Then:  AUTHFRDS row inserted with AUTH-FRAUD=Y and FRAUD-RPT-DATE=today

Given: CBPAUP0J batch runs
When:  CBPAUP0C purges authorizations older than retention period
Then:  expired IMS records deleted
And:   ACCT-CURR-BAL restored for unmatched authorizations

🔧 Technical Foundation

ComponentResponsibility
COPAUA0C.cblMQ-triggered: process authorization request, write IMS, send response
COPAUS0C.cblCICS: display pending authorization summary
COPAUS1C.cblCICS: display authorization detail, initiate fraud flag
COPAUS2C.cblCICS: insert fraud record into DB2 AUTHFRDS
CBPAUP0C.cblBatch: purge expired IMS authorizations, restore credit
IMS DBPAUTP0 (HIDAM)Authorization storage (hierarchical)
DB2 AUTHFRDSFraud analytics table
MQ Authorization QueueInbound authorization requests
MQ Reply QueueOutbound authorization responses

DB2 AUTHFRDS Schema (key columns)

CARD_NUM       CHAR(16)     PK -- Card number
AUTH_TS        TIMESTAMP    PK -- Authorization timestamp
AUTH_RESP_CODE CHAR(2)         -- AP=Approved, DC=Declined
TRANSACTION_AMT DECIMAL(12,2) -- Requested amount
AUTH_FRAUD     CHAR(1)         -- Y=Fraudulent
FRAUD_RPT_DATE DATE            -- When flagged

⚠️ Setup Note

Update the DB2 schema name in COPAUS2C.cbl to match your environment before compiling. IMS DBDs (DBPAUTP0, DBPAUTX0) and PSBs (PSBPAUTB, PSBPAUTL) must be created by an IMS DBA.
